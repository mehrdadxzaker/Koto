## Repair

A retained stock episode saved an incorrect implementation, printed a normal
example twice, then reported completion. V8 reduced the reasoning allowance to
16 after the first successful post-patch command even though it only printed.
V9 keeps the solving allowance for that command and asks for assertions covering
the original requirements. Its finishing hint requires observed assertion intent
in the latest correlated successful command after a saved native patch.

The observation recognizes a bounded direct `python3 -c` script with Python
assertion syntax or an imported unittest TestCase assertion. It parses code; it
never executes it. Printed assertion text, shell chains, optimization flags,
unknown command forms and oversized or invalid scripts stay conservative. A
pending command retains its originating intent only if no later native patch
has been saved. Failed, malformed, unbound or unfinished tool work cannot inherit
an earlier success.

Assertion syntax can be trivial, unreachable or insufficient. This observation
does not prove execution, coverage, correctness or qualification. The host's
actual tool result stays unchanged. No assertion, test data or command is added,
rewritten or executed by this observation.

A retained list-key episode saved code that passed the independent checker but
repeated a failing newly authored check of KeyError's formatted message. The
task required an exception type. V9 explains that an authored check can add an
assumption absent from the original specification. Correlated KeyError and
AssertionError feedback distinguishes the type, argument and formatted message,
while preserving any original message requirement and every existing check.
The checkpoint supplies static guidance, without copying program output into
instructions or deciding an expected value.

V9 offers a text replacement helper for an identified native patch tool. When
offered, it comes first, followed by the function-case helper and plain Python
script fallback. It accepts a relative file path and model-supplied old/new text,
then compiles a native patch with the required line prefixes. This is a
line-oriented LF interface with the native tool's final-newline behavior; it
does not promise exact byte replacement of a missing terminal newline. It never reads,
searches or writes files itself, supplies replacement code, or repairs a native
patch argument. The existing host validates and executes the patch with its
normal permissions. Original native tools stay available. Guidance names the
actual collision-safe
aliases and respective arguments. Each retains its existing compiler and shares
the existing bounded identity, buffering and compiled-command limits. When only
one catalog slot remains, the function-case helper takes priority. The host's
original tools retain their bodies and relative order; tool choice and
non-automatic host restrictions stay unchanged.

The function-case helper takes model-supplied examples and expectations. Each
call supplies an `arguments` object keyed by actual saved-function parameter
names, with the same supplied names across cases. Closed, disjoint schema
branches distinguish successful returns from expected exceptions: identity
checks belong only to successful returns. State and batch fields also use names.
The compiler maps these names to internal indices and calls the saved function
with the original names and values. All cases must bind to its actual signature
before any call executes. Omitted defaults stay omitted; positional-only
parameters require the script fallback. No signature or expectation is repaired.
Its existing optional batch composition repeats/combines those same batches to
compare sequential rejection with combined acceptance and state preservation.
Use that property only when the original specification supports it; atomicity
alone is insufficient. No independent oracle, invented operation, expected value
or comprehensive coverage is supplied. The script helper still accepts plain
source unchanged. Both compile commands for the existing host to execute.

After correlated failed check-input feedback, v9 explicitly asks the model to
correct its case data or use the script fallback while keeping the saved task
signature. Such feedback does not establish passing assertions or an
implementation defect. Successful or unbound output cannot trigger this advice.

V9 also restores native patch-format recovery after the latest correlated
numbered-hunk rejection or invalid-hunk error. Pending, later, unknown or duplicate feedback cannot
reuse that advice. Koto never repairs a patch argument or declares it executed.

## Controls and compatibility

V9 retains v8's script helper, native identity mapping and transparent reasoning
continuation. Effort/output controls remain the same: low256, minimal128,
medium512 and high-or-above1024, bounded by the output cap. Initial32 and
after-patch64 hints retain their low/minimal scope. A qualifying post-patch
successful command receives at most16; explicit `none` remains0.

Select the profile only in a reviewed setup-v5 declaration. Coding evidence and
probe v4 or newer bind the exact capability, local model, native transport and
execution generation. Development probe v5 retains its separate180-second
permission. Earlier versions, ambiguous harnesses, other models and missing
native transport are rejected. Ordinary unqualified coding remains blocked.

Revoke any probe and disconnect before changing profiles. A new profile requires
fresh evidence; existing v8 receipts do not authorize v9 or an in-flight switch.
Normal Codex settings and history consent are unchanged by disposable studies.

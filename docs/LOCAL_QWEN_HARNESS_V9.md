## Repair

A retained stock episode saved an incorrect implementation, printed a normal
example twice, then reported completion. V8 reduced the reasoning allowance to
16 after the first successful post-patch command even though it only printed.
V9 keeps the solving allowance for that command and asks for assertions covering
the original requirements. Its finishing hint requires observed assertion intent
in the latest correlated successful command after a saved native patch.

The observation recognizes a bounded direct `python3 -c` script with Python
assertion syntax or an imported unittest TestCase assertion. It parses code; it
never executes it. Printed assertion text, shell chains, optimization flags,
unknown command forms and oversized or invalid scripts stay conservative. A
pending command retains its originating intent only if no later native patch
has been saved. Failed, malformed, unbound or unfinished tool work cannot inherit
an earlier success.

Assertion syntax can be trivial, unreachable or insufficient. This observation
does not prove execution, coverage, correctness or qualification. The host's
actual tool result stays unchanged. No assertion, test data or command is added,
rewritten or executed by this observation.

A retained list-key episode saved code that passed the independent checker but
repeated a failing newly authored check of KeyError's formatted message. The
task required an exception type. V9 explains that an authored check can add an
assumption absent from the original specification. Correlated KeyError and
AssertionError feedback distinguishes the type, argument and formatted message,
while preserving any original message requirement and every existing check.
The checkpoint supplies static guidance, without copying program output into
instructions or deciding an expected value.

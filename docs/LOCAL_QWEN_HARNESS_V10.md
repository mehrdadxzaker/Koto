# Compact local Qwen coding profile

`qwen_code_v10` selects the opt-in `qwen-code.v10` profile for the installed
Qwen3-14B-Q4_K_M and native `codex_llama_v1` transport. It is default off and
unqualified. The default and v1–v9 profiles retain their existing request
contracts. Codex retains instructions, original tools and tool choice, approvals,
sandbox, execution, continuations and the agent loop.

## Request module

The Router request module owns local guidance, helper admission and compute
hints. The transport adapter retains native tool translation, response identity,
stream buffering and compiled-command limits. Both use the original correlated
native history; the request module shares one progress observation across advice
and compute allocation.

V10 offers two existing adapters: plain Python source compiled to the original
native command tool, and exact model-supplied LF text compiled to the original
native patch tool. The model supplies source, paths and checks. Koto neither
executes commands nor reads or repairs the target code. All original native tools
remain available with their bodies, relative order and tool choice unchanged.
Only an unambiguous original native declaration admits a helper; catalog limits,
nonautomatic choice and collision-safe aliases retain their existing rules. The
script helper receives the only free catalog slot before the text helper.

One protocol gives the model the actual admitted aliases and their argument
names. V10 omits the function-case helper and its schema, generated driver and
overlapping instructions. This reduces the active model interface; it does not
remove the legacy compilers or change older profiles.

## Coding hypothesis

Retained v9 stock checks passed while omitting cumulative demand and rollback
assertions. One list-key check found an allowed unhashable value, but the model
then introduced a missing import and never successfully checked the correction.
Other attempts repeatedly supplied nonexistent native patch context. These
observations distinguish insufficient model reasoning and verification from a
compiler or host execution defect.

V10 gives generic, requirement-dependent guidance: apply an atomic batch in order
against private evolving state, then commit after complete success. Check a valid
step followed by failure, repeated operations and the complete unchanged state
after the specified exception. Where supported values may be unhashable, compare
keys by equality; hashing, sorting or serialization is not an equality substitute.
A missing required key differs from a present `None`. Import the saved code,
repair actual failures and rerun the same compact assertions after the final edit.
No task identifier, benchmark input, expected value or independent oracle is
inserted into requests. The model still must derive and execute meaningful checks.

Compute hints remain the v9 values: low256, minimal128, medium512, high-or-above1024,
bounded by output; initial32, after-patch64 and verified post-patch16 under their
existing conditions. Explicit `none` stays0. Failed, pending, ambiguous or
unresolved work cannot inherit completion. Recognized assertion syntax remains
intent only, not execution, requirement coverage or task correctness.

## Evidence and qualification

Fresh capability, exact-model/native-transport and execution-generation evidence
is required. Existing v8/v9 evidence cannot authorize v10 or an in-flight switch.
Revoke a probe and disconnect before changing profiles. The development probe's
180-second permission remains separate from ordinary 90-second qualification;
unqualified ordinary local coding remains blocked.

The predeclared comparison uses the original six goals, starting sources and
independent checks with three alternating v8/v10 pairs, one installed model and
unchanged native controls. Full success requires a changed saved implementation,
the unchanged passing checker, normal native completion and client exit0. Saved
checker success and native completion are reported separately. All failures and
earlier negative evidence are retained. Reused development tasks cannot establish
held-out or general coding qualification.

The comparison is pending; regression tests and interface size alone do not
establish a coding improvement.

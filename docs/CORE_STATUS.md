## Implemented source

- Native Codex/ChatGPT and Claude Code account discovery, native sign-in or
  private client installation, and optional pinned local model/runtime
  acquisition. Native subscription use does not require provider API keys.
- Conversational CLI project selection, editable/revalidated plans, remembered
  workers and model choices, and saved review/integration/continuation without
  copying session-directory paths. Shared setup and plan APIs support later
  delivery adapters.
- Shared concurrent scheduling, separate Git worktrees, bounded output/input,
  per-agent stop controls and retained results. Preflight starts no model and
  changes no native account configuration.
- Platform terminal helpers for macOS and Linux PTYs and Windows ConPTY. The
  Windows helper also owns pipe commands through a Job Object. Helpers are built
  explicitly using existing host tools and verified before launch; compilation
  does not occur during an agent launch. Reviewed Windows supervision adds a
  single coalescing resize worker, bounded shutdown-phase diagnostics and explicit
  ConPTY console standard handles. Phase telemetry supplies no cleanup authority;
  confirmed workload ownership remains required.
- Structured native observers with declared capabilities, captured native IDs,
  completion/failure state and available token usage. Native terminal screens
  remain human interfaces and are not scraped for identity or permissions.
- Explicit native and local continuation in the original worktree and captured
  conversation. Origin settings and the exact ID must match. Settled process
  cleanup is required; Koto never substitutes a latest session or retries
  automatically.
- Contribution review and token-approved integration into a separate branch.
  Resumed contributions apply the delta since the retained successful snapshot.
  Receipts bind the reviewed tree and source/target history.
- Explicit conflict-resolution acknowledgement: the operator resolves and commits
  in the integration worktree, then approves its exact current commit. Pending
  conflicts or unconfirmed cleanup block integration and resume. The original
  checkout is not updated, and ambiguous outcomes retain a lock.
- Memory admission and monitoring with retained first-failure diagnostics,
  observable Linux cgroup limits/headroom, macOS native available-memory
  estimates, separate raw-free values and a configurable prompt-cache RAM
  allowance, defaulting to 0 MiB.
  Socket/file-descriptor exhaustion remains a fatal recovery boundary.
- The reviewed `0635143` shared cancellation fix guards external error-code
  types, observes original monitor/completion promises immediately, and stops and
  joins owned cleanup before reporting monitor failure. Package identity and
  source/helper CI are verified, as is one installed client-setup cancellation
  branch. Actual Windows native work and controlled runtime stop are now
  observed. The separate diagnosed CLI ownership boundary has a reviewed
  two-file repair and accepted uninstrumented control-return observations.

- The reviewed `caa5ca6` CLI handoff contract acknowledges a live replacement
  raw-input owner explicitly, restores prior raw mode on unsuccessful transfer,
  and stops owned work on real input loss or partial-control failure. Final stdin
  cleanup covers constructor-before-return failures without private internals.

See [native sessions](NATIVE_SESSIONS.md) and
[project sessions](PROJECT_SESSIONS.md) for protocol and integration boundaries.
